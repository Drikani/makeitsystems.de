# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

This is the source for makeitSYSTEMS, a static Jekyll site (German-language personal/company page with "Über mich", "Lebenslauf", and "Impressum" pages). It was migrated from GitLab to GitHub and is deployed via GitHub Pages (see "CI / deployment" below).

## Commands

```bash
bundle install       # install Jekyll 4.4 and dependencies (Ruby >= 3.1 per Gemfile)
bundle exec jekyll serve   # run local dev server with live rebuild
bundle exec jekyll build   # build the static site into _site/
```

There are no tests or linters in this repo. There is CI (see "CI / deployment" below), but it only builds and deploys — it doesn't check anything before merge.

## Architecture

Standard Jekyll layout/include structure with three real top-level pages (not anchor tabs — that was the old Materialize-era structure; it was split apart when the tabs were rebuilt as real navigation):

- [_layouts/default.html](_layouts/default.html) is the only layout. It assembles `head`, `header`, `nav`, page `content`, and `footer` includes. The site ships **zero JavaScript** — jQuery and the cookie-consent popup were removed once nothing on the site set cookies anymore (Discord/Twitter embeds were already gone; the cookie popup's own consent cookie was the last one). If you add something that needs client-side JS again, it starts from scratch — there's no vendored library lying around to lean on anymore.
- Three top-level pages, each with its content **written directly in the page**, not via a page-specific include: [index.html](index.html) (`/`, "Über mich"), [lebenslauf.html](lebenslauf.html) (`/lebenslauf.html`), [impressum.html](impressum.html) (`/impressum.html`). Each sets `title:` in its front matter, used by `head.html` for the `<title>` tag. (There used to be one big include per page, e.g. `_includes/me.html` — that layer was removed; edit the page file itself now.)
- [_includes/nav.html](_includes/nav.html) defines the tab bar (Bootstrap `nav nav-tabs nav-fill`) as real links to those three pages; each link's `active` class is set server-side via `{% if page.url == '...' %}`, not JS — there's no client-side tab-toggle script anymore. If you add a fourth page, update this file's links/active-checks too — nothing generates that list automatically.
- Repetitive content lives in [_data/](_data) YAML files and is rendered with `{% for %}` loops instead of one include per item:
  - `hardskills.yml`, `softskills.yml` — flat string lists, looped into `.chip` spans on `lebenslauf.html`.
  - `timeline.yml` — list of `{time, title, text}`; `text` may contain raw HTML (e.g. an `<a>`) and is output unescaped, looped into the `.timeline` list on `lebenslauf.html`.
  - `sources.yml` — list of `{name, url}`, looped into the "Quellen" `list-group` on `impressum.html`.
  - `privacy_sections.yml` — list of `{title, body}`, one entry per Datenschutz card on `impressum.html`; `body` is a raw HTML block (paragraphs, sometimes a `<ul>`), output unescaped via `{{ section.body }}`. This one file replaced seven near-identical `_includes/imprint/*.html` partials (SSL, cookies, disclaimer, logs, linkedin, rights, ads).
- Styling is Bootstrap 5 (via the `bootstrap` gem, see below) plus a small custom layer in [_sass/](_sass) (`_custom.scss`/`_custom-dark.scss`/`_main-variables.scss`/`_roboto.scss`/`_color-variables.scss`), compiled from [css/main.scss](css/main.scss) into `css/main.css`; `_config.yml` sets `sass_dir: _sass`, `style: compact`, and `quiet_deps: true`.
  - **Masonry-style card grids use the `.masonry` utility class (in `_custom.scss`), not a JS library.** Progressive enhancement, no JS at all: a `column-count` + `break-inside: avoid` multi-column layout is the baseline, and `@supports (grid-template-rows: masonry) or (display: grid-lanes)` switches to native CSS Grid masonry where the browser actually supports it (Safari, unflagged, as of mid-2026 — Chrome/Firefox still behind a flag). Used on `index.html`'s hobby cards and `impressum.html`'s Datenschutz cards. This replaced Salvattore (`js/salvattore.js`, `_sass/_salvattore.scss`, the `#grid[data-columns]`/`.item` markup) — removed entirely, no longer a dependency. As `grid-template-rows: masonry` support broadens, more visitors get it automatically; no code change needed. If `display: grid-lanes` ships with genuinely different syntax (not just an alias), that `@supports` block will need its own rules, not just the current masonry declarations reused.
  - **`.card`/`.card-body` need an explicit `color` in both `_custom.scss` and `_custom-dark.scss`.** Bootstrap's `.card-body { color: var(--bs-card-color); }` resolves to nothing when `--bs-card-color` is unset (which it is here), so it falls back to `--bs-body-color` — a CSS custom property that stays pinned to Bootstrap's *light-mode* value, because this site's dark mode is a `prefers-color-scheme` media query, not Bootstrap's `[data-bs-theme="dark"]` attribute mechanism. Without the explicit override, card text in dark mode renders near-black-on-dark-blue-grey — nearly illegible. If a future `.card`-based component looks unreadable specifically in dark mode, check this first before assuming it's a new bug.
  - **Bootstrap and Font Awesome come from Ruby gems (`bootstrap`, `font-awesome-sass`), not vendored files or a CDN link.** [_plugins/bootstrap_sass.rb](_plugins/bootstrap_sass.rb) adds `Bootstrap.stylesheets_path` to Jekyll's Sass `load_paths` at `:site, :after_init`, so `@import "bootstrap/..."` in `css/main.scss` resolves into the installed gem. [_plugins/font_awesome_sass.rb](_plugins/font_awesome_sass.rb) does the same for `@import "font-awesome/..."`, **and** additionally registers a custom `Jekyll::StaticFile` subclass on `:site, :post_read` that copies just the two Solid-style font files (`fa-solid-900.woff2`/`.ttf`) from the gem into `fonts/font-awesome/` in the build output — Sass only handles the CSS half (`@font-face` rules), it can't move binary font files on its own, so this is the piece that makes the fonts actually present in `_site/`. Only the Solid style is imported (`font-awesome/functions`, `variables`, `mixins`, `core`, `icons`, `solid`) — Regular and Brands are skipped since nothing on the site uses them. Both plugins only work because deployment runs `bundle exec jekyll build` ourselves in a GitHub Actions runner (see "CI / deployment"), not GitHub Pages' legacy branch-based auto-build — that flow whitelists a fixed plugin list and would silently ignore custom `_plugins/`, breaking both.
  - **Icons are Font Awesome (`fa-solid fa-<name>`), not Google's Material Icons.** The old Material Icons setup (`fonts.googleapis.com` `<link>` in `head.html`, `<i class="material-icons">name</i>` markup with the icon name as text content) was removed so the site makes zero requests to third-party domains. Font Awesome markup is structurally different: empty `<i>` tags, icon selected via CSS class (`<i class="fa-solid fa-heart"></i>`), not text content — keep that in mind if adding a new icon or reading old commits/screenshots. `_data/hobbies.yml`'s `icon:` field holds a bare Font Awesome slug (e.g. `globe`), interpolated into `fa-solid fa-{{ hobby.icon }}` by `index.html`.
  - `quiet_deps: true` isn't cosmetic: without it, Bootstrap's large volume of internal Sass deprecation warnings crashes the `sass-embedded` compiler outright during a real Jekyll build (reproduces even on a trivial file — a `sass-embedded`/dart-sass issue, not a config mistake).
  - **Don't name a custom `_sass/` partial the same basename as `css/main.scss`.** `_sass/main.scss` (imported as `@import "main"`) reliably broke the whole build with a garbled `expected "{"` error blamed on an unrelated line — a real dart-sass import-resolution bug triggered by the entry file and an imported partial sharing a basename. That's why the custom layer is `_custom.scss`/`_custom-dark.scss`, not `main.scss`/`main-dark.scss`.
  - `_main-variables.scss` overrides Bootstrap variables (`$font-family-sans-serif`, `$h1-font-size`..`$h6-font-size`, etc.) to match this site's pre-Bootstrap look (self-hosted Roboto, Materialize-era heading scale), plus `$fa-font-path` for Font Awesome (must have **no** trailing slash — its own `fa-font-path()` function appends one, a trailing slash here would double it) — read its comments before assuming a "default" value for any of these.
  - `_color-variables.scss` is Materialize's old Material Design color palette (map + a `color()` lookup function), kept only because `_custom.scss`/`_custom-dark.scss`/`_main-variables.scss` still reference it. Its internal map variables are prefixed `mz-` (`$mz-blue`, `$mz-red`, …) specifically because they'd otherwise collide with Bootstrap's own `$blue`/`$red`/etc. primitives in the shared legacy `@import` namespace and silently corrupt Bootstrap's color system.
- Static assets (images) live in [assets/](assets). The `js/` directory no longer exists — see above. There's no Discord or Twitter embed anymore (removed along with `jekyll-twitter-plugin` and `js/detectColorScheme.js`, which existed solely to theme the Twitter widget).
- `_site/` is the Jekyll build output, gitignored (standard Jekyll setup) — regenerate it locally with `bundle exec jekyll build`.
- [_config.yml](_config.yml) holds site-wide data meant to be reused instead of hardcoded in HTML: `contact.*` (name, company, address, domain — shown on `impressum.html`) and `email` (top-level, used both for the `mailto:` link and site metadata). `copyright_start_year` drives the footer's copyright line (see below) — update it only if the actual site launch year turns out to be wrong (currently a best guess from repo history, not confirmed). `url`/`baseurl` are set for the GitHub Pages project-page path (`https://drikani.github.io/makeitsystems.de`), **not** `/` — if a custom domain is ever set up instead, both need to change (and the [pages.yml](.github/workflows/pages.yml) workflow's `--baseurl` override, which currently mirrors this, would need to go too, since custom-domain Pages serves from the root).

## CI / deployment

Branching model: work happens on `develop`; pushing/fast-forwarding `develop` into `main` is what ships it. Both workflows below trigger on push to `main` and assume that push was a fast-forward from `develop` — no direct commits to `main`, no merge commits. If that assumption is ever violated (e.g. a PR merge with a merge commit), the release changelog will no longer accurately reflect "what changed on develop."

- [.github/workflows/pages.yml](.github/workflows/pages.yml) — builds with Jekyll and deploys to GitHub Pages via the modern Actions-based flow (`actions/configure-pages` + `actions/upload-pages-artifact` + `actions/deploy-pages`, OIDC-based, no token/branch juggling). Requires the repo's Pages source to be set to "GitHub Actions" in Settings → Pages (a one-time manual step in GitHub's UI, not something this workflow file can do itself).
- [.github/workflows/release.yml](.github/workflows/release.yml) — creates a dated GitHub Release (`vYYYY.MM.DD`, with a `.N` suffix appended if a same-day tag already exists) whose body is `git log <last-tag>..HEAD --no-merges`, i.e. every commit since the previous release. Uses the `gh` CLI (preinstalled on GitHub-hosted runners) rather than a third-party release action.

The site sets **no cookies at all** (confirmed: `grep -rn document.cookie` finds nothing once the removed cookiepopup.js is gone) — there's no cookie-consent banner because there's nothing to consent to. Before adding anything that sets a cookie or loads a third-party embed (analytics, another social widget, etc.), reconsider whether a consent mechanism needs to come back too — it doesn't happen automatically.

[_includes/footer.html](_includes/footer.html) computes the copyright line at build time: `{{ site.contact.domain }} © {{ site.copyright_start_year }}–<current year>`, collapsing to a single year if they match. `site.copyright_start_year` is an integer in YAML but the Liquid comparison needs a string, hence the `| append: ""` coercion in that file — don't compare it to `current_year` directly or the range/single-year branch picks wrong silently (no error, just wrong output).
